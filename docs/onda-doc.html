The problem that ships in every box

A JBL speaker arrives in a box large enough to hold a fully readable manual. Instead, it contains a folded slip of paper with text so small it requires a magnifying glass. Within six months, a software update has changed the interface and every instruction on that slip is wrong. Users are more confused after reading it than before.

This is not a JBL problem. It is the industry standard — from Apple to every small business that has ever printed an instruction sheet.

What printed documentation always does

  • 4-point text that is unreadable without glasses — failing seniors, ND users, and anyone in poor lighting
  • No visual orientation — users can't identify what a control is before they're told what it does
  • Printed in thousands — obsolete within months when software or hardware ships an update
  • Static by nature — no way to correct, extend, or translate without a new print run
  • No context awareness — the same sheet for every user, regardless of where they are in the product

Digital help pages solve the obsolescence problem — but most just move the same bad model to a screen. Small text, no orientation, no numbered callouts, and still no connection to where the user actually is.

The numbered callout — orientation before instruction

Most help documentation describes what features do. It assumes the user already knows where those features are. That assumption is wrong for a first-time user, a senior, a person with low vision, or anyone using the software in a second language.

The ONDA Doc model orients first. Every screen gets a screenshot. Every control on that screenshot gets a numbered callout. Below the screenshot, each number maps to a plain-language explanation in large, readable text.

The living document architecture

ONDA Replay already runs on this model. The app contains only a single URL. When a user taps Help, that URL opens — and the page that loads is a web document that can be updated at any moment, by anyone with access to the repository, without submitting a new version to the App Store or Google Play.

Printed manual / baked-in help

  • Wrong the moment the product updates
  • Thousands of copies, impossible to recall
  • 4pt text, no accessibility
  • Same content for every user
  • Requires a new release to fix a typo

ONDA Doc

  • Update the page — every user sees it instantly
  • Nothing to print, nothing to recall
  • 18pt+ text, high contrast, screen-reader friendly
  • Context-aware — opens to the right section automatically
  • Fix a typo in 30 seconds from any device

The page is a living document. When the UI changes — a button moves, a feature is renamed, a new option appears — one image is updated on the web. Every user of every version of the app sees the correction immediately.

The lever for IT professionals

What this means for a firm like FourFold IT

An IT firm visiting a client already knows where the documentation fails. They see it at every shop — the software the client uses has controls that nobody can identify, help text that hasn't been updated in two years, and a support cost driven almost entirely by confusion that a good orientation layer would have prevented. ONDA Doc is the product they can sell to fix it.

This is not a niche opportunity. Every business that uses software — which is every business — has this problem. The IT firm does not need to build anything. They do the intake: walk the screen with the client, number the controls, write plain-language explanations, take the screenshot. ONDA Doc hosts and delivers it.

  1. 1
    IT firm identifies the software the client struggles with
    Could be their POS system, their CRM, their accounting software, their own custom app. Any screen where users get lost.
  2. 2
    Takes a screenshot of each key screen
    One screenshot per screen. No special equipment — a phone camera or screen capture tool is enough.
  3. 3
    Numbers every control on the screenshot
    Each button, field, icon, and menu gets a number. The user now has a map before they read a single word.
  4. 4
    Writes plain-language explanations for each number
    Large text. No jargon. Written for the person who has never seen this screen before. Accessible to seniors, ND users, ESL users.
  5. 5
    Publishes to ONDA Doc
    The client gets a URL. That URL can be shared via QR code, posted on the wall near the device, or embedded in the software itself.
  6. 6
    When anything changes, the IT firm updates one page
    No reprint. No new release. No support call about the button that moved. Thirty seconds from change to fix, for every user at once.
